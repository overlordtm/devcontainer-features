# Shell History

Preserves shell history across container rebuilds for **bash**, **zsh**, and **fish**.

## Example Usage

```jsonc
{
    "features": {
        "ghcr.io/overlordtm/devcontainer-features/shell-history:0": {}
    }
}
```

## What it does

- Creates a Docker named volume named `${devcontainerId}-shell-history` and mounts it at `/dc/shell-history`.
- Writes shell configuration to `~/.config/shell-history/`:
  - `bash.sh` sets `HISTFILE=/dc/shell-history/.bash_history`, `HISTSIZE`, `HISTFILESIZE`, and appends every command with `history -a` so history survives an abrupt container stop.
  - `zsh.sh` sets `HISTFILE=/dc/shell-history/.zsh_history`, `HISTSIZE`, `SAVEHIST`, and enables `INC_APPEND_HISTORY`.
  - `config.fish` links `~/.local/share/fish/fish_history` (or `$XDG_DATA_HOME/fish/fish_history`) to the volume.
- Sources those files from `~/.bashrc`, `~/.zshrc`, and `~/.config/fish/config.fish`, adding the source line only once.
- On first container creation, imports existing `~/.bash_history`, `~/.zsh_history`, and fish history into the volume and repairs the fish history link.

The shell configuration is written at image build time for the Feature's remote user, so it is present even when lifecycle hooks are skipped (for example in `devcontainer features test`). Shells that are not installed are still configured, so installing zsh or fish later works without rebuilding.

## Options

| Option | Description | Type | Default |
| --- | --- | --- | --- |
| `historySize` | Number of commands to keep in bash and zsh history (`HISTSIZE`/`HISTFILESIZE`/`SAVEHIST`). Fish manages the size of its own history file. | string | `10000` |

## Notes

- The volume is scoped to the dev container ID, so each project keeps its own history while sharing it across rebuilds. To wipe it, remove the volume with `docker volume rm <devcontainerId>-shell-history`.
- This Feature intentionally scopes history per dev container. If you need one history shared by every project on a Docker host, configure `HISTFILE` and the fish history link yourself instead of using this Feature.
- Interactive login shells that do not read `~/.bashrc` will not pick up the bash configuration. Most Dev Container base images source `~/.bashrc` from `~/.profile`.
- If a dotfiles tool replaces `~/.bashrc`, `~/.zshrc`, or fish's `config.fish` after container creation, re-add the `~/.config/shell-history/` source lines.
- History files can contain secrets typed into a shell. Treat the volume as sensitive.

## Testing

```bash
devcontainer features test -f shell-history -i mcr.microsoft.com/devcontainers/base:debian --project-folder .
devcontainer features test -f shell-history --skip-autogenerated --project-folder .
```

The shared test checks the volume, generated configuration, and bash/zsh history writing. Fish is exercised by the `fish` scenario, which installs fish in the test container.
